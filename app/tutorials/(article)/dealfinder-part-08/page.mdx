## The permission problem

The official APIs cover the headline retailers — Costco, Macy's, BestBuy, eBay. But a query for "noise cancelling headphones" surfaces results from independent Shopify stores, specialty audio retailers, and aggregator pages that none of those APIs know about. You need those listings to catch deals the mainstream sources miss.

Every data-acquisition decision has three dimensions:

- **Legal**: does the ToS permit programmatic access? Does `robots.txt` disallow crawling?
- **Technical**: will you be blocked (rate limits, CAPTCHAs, IP bans)?
- **Ethical**: are you pulling data at a rate the server can absorb? Are you creating user value or just extracting value from someone else's infrastructure?

Getting this wrong has real consequences: a court injunction (hiQ v. LinkedIn litigated computer-fraud claims for six years), an IP ban that kills your production connector overnight, or simply a rep for being an abusive client. Getting it right means the data layer keeps working indefinitely.

## Four tiers of data acquisition

The companion organizes every source into a tier based on how permission is established. The `LIVE_SOURCES` list in `live_sources.py` orders connectors by tier so the cheapest, most permissive sources run first:

**Tier 1 — Official API.** `RapidApiSource`, `BestBuySource`, `EbaySource`. A first-party endpoint with API keys, documented rate limits, and a ToS that explicitly grants programmatic access. No judgment call needed. Use freely within the documented limits.

**Tier 2 — Managed scraping.** `ApifySource`. Apify operates the scraper; you call their HTTP API. The scraping ToS question is Apify's to answer for their actors — and their actors are built to respect robots.txt. You are responsible for ensuring you only use actors covering data you're allowed to use, but you are not the entity doing the scraping.

**Tier 3 — Public structured feed.** `ShopifySource`. Shopify documents the `/products.json` endpoint in their developer docs; it's indexed by search engines and served without authentication. The data is intentionally public. No key, no CAPTCHA, no JavaScript rendering — just a JSON response. Still check robots.txt for the specific store.

**Tier 4 — Broad-web crawl.** `FirecrawlSource`. Page-level HTML scraping via Firecrawl's search API. Noisier output, more likely to encounter `robots.txt` disallows or anti-bot measures. Use only when tiers 1–3 miss the retailer, and check the domain's robots.txt before including it.

This ladder shapes the architecture of `LIVE_SOURCES`: tier 1 runs first, tier 4 last. The ordering is not arbitrary — it controls which source price gets credited in the merged output.

<Callout tone="note">
**The permission surface is hardening in real time — DealFinder is an "Agent" bot.** As of July 2026, Cloudflare's AI Crawl Control (on every plan, including Free) lets any site sort incoming crawlers into three lanes — **Search**, **Agent**, and **Training** — and allow or block each independently, with no WAF rule required. On **Sept 15, 2026** Cloudflare flips the default on ad-monetized pages to block *both* Training and Agent bots. DealFinder's scraper is squarely an **Agent**-class crawler (it fetches on behalf of a user's query), so expect more sites to return 403 to your tier-4 crawls over time — and note the trap for multi-purpose crawlers: a site that blocks "Training" also blocks a crawler that's *evaluated under both* Search and Training policies. This is exactly why the tier ladder puts official APIs first: they're the access path that doesn't erode as bot-blocking tightens.
</Callout>

## ApifySource: managed scraping with a clean API surface

`ApifySource` wraps the Apify actor run API. The interface is identical to every other `DealSource`: you call `.search(query, limit)`, you get back `list[Product]`. Apify handles the rendering, CAPTCHA solving, proxy rotation, and ToS compliance for their actors.

The `country`/`language` parameters and the currency guard below earn their lines: in a real run without them, the actor returned Mercado Libre listings priced in Mexican pesos — a "$4,099" Sony WH-1000XM5 — that the connector would have labeled USD. One unguarded connector defaults away an assumption (everything is US-market dollars) that every median and deal score downstream silently depends on.

<Callout tone="note">
**Get your Apify token (free, ~2 minutes).** [Apify](https://apify.com/) is a managed scraping platform: instead of running a headless browser yourself, you invoke a hosted scraper (an "actor") over HTTP and get JSON back — the scraping runs on Apify's infrastructure. DealFinder uses the [Google Shopping actor](https://apify.com/automation-lab/google-shopping-scraper).
1. Sign up at [console.apify.com](https://console.apify.com/) (free plan includes a monthly usage credit — plenty for this course).
2. Go to **Settings → API & Integrations** and copy your **Personal API token** (`apify_api_…`).
3. Add `APIFY_TOKEN=apify_api_…` to the companion's `.env`. (`APIFY_ACTOR` already defaults to the right actor.)
</Callout>

```python
# live_sources.py — ApifySource.search() (real implementation)
def search(self, query: str, limit: int = 15) -> list[Product]:
    token = os.getenv("APIFY_TOKEN")
    if not token:
        return []
    actor = os.getenv("APIFY_ACTOR", "automation-lab~google-shopping-scraper")
    r = httpx.post(
        f"https://api.apify.com/v2/acts/{actor}/run-sync-get-dataset-items",
        params={"token": token},
        # country/language pin the marketplace: without them the actor mixes in
        # localized listings (Mercado Libre in MXN, etc.) whose prices would
        # masquerade as USD and poison the cross-source median.
        json={"queries": [query], "maxResults": limit, "country": "us", "language": "en"},
        timeout=180,
    )
    body = r.json()
    out = []
    for it in body if isinstance(body, list) else []:
        price = it.get("priceNumeric") or _f(it.get("price"))
        if not price:
            continue
        if (it.get("currency") or "USD").upper() != "USD":
            continue  # never let a foreign-currency price into USD math
        merchant = it.get("merchant") or "shopping"
        out.append(Product(
            id=f"apify-{(it.get('title') or '')[:40]}",
            title=(it.get("title") or query)[:120],
            brand=merchant,
            category="product",
            price=float(price),
            currency=it.get("currency") or "USD",
            url=it.get("productUrl") or "",
            source=f"{self.name}:{merchant}",
            image_url=it.get("imageUrl"),
        ))
    return out
```

Three things to notice. First, `timeout=180`: Apify runs the actor synchronously and returns all results when the run finishes — that can take two to three minutes for a Google Shopping query. The long timeout is intentional; do not reduce it. Second, `price = it.get("priceNumeric") or _f(it.get("price"))`: `priceNumeric` is a pre-parsed float that the actor populates when it can; the `_f()` fallback handles the string form. Third, `brand=merchant`: Apify returns the merchant name, not the manufacturer. The same title-brand extraction from Part 1 applies here before the product enters the deal-score pipeline.

The `APIFY_ACTOR` env var points to the default Google Shopping actor (`automation-lab~google-shopping-scraper`). This is the same actor that produced the RapidAPI + Apify entries in the snapshot (`electronics-2026-07.json`). You can swap it for a different actor by changing the env var — the `ApifySource` class does not care which actor you use, only that it returns items with `title`, `priceNumeric` or `price`, `productUrl`, and `merchant`.

<Callout tone="note">
**Snapshot provenance.** The 270-item `electronics-2026-07.json` snapshot was built from RapidAPI + Apify (real Google Shopping). eBay is excluded from the snapshot because the companion runs against the eBay sandbox, which returns test data. The snapshot's `marketplace` field records `"RapidAPI"` or `"Apify"` for every item — that's how you can trace which connector contributed each listing.
</Callout>

## AmazonSource: the big retailer the feeds miss

Google Shopping — the firehose behind RapidAPI and Apify — carries Walmart, Target, Best Buy, Costco, and dozens more, but **almost no Amazon**: Amazon barely participates in Google Shopping, its Product Advertising API requires an approved affiliate with prior qualifying sales, and it blocks direct scraping hard. So the one retailer everyone asks about is exactly the one the easy feeds don't give you.

The fix is the *same managed-scraping pattern* as `ApifySource` — a hosted actor, invoked over HTTP, reusing the `APIFY_TOKEN` you already have. `AmazonSource` calls the `junglee/Amazon-crawler` actor, which takes an Amazon search URL (built from the query) and returns structured product rows:

```python
class AmazonSource:
    name = "Amazon"
    tier = 2                       # managed scraping: ~20-25s, costs credits
    _actor = "junglee~Amazon-crawler"

    def available(self) -> bool:
        return bool(os.getenv("APIFY_TOKEN"))   # no new key — reuses Apify

    def search(self, query: str, limit: int = 15) -> list[Product]:
        token = os.getenv("APIFY_TOKEN")
        if not token:
            return []
        search_url = "https://www.amazon.com/s?k=" + quote_plus(query)
        r = httpx.post(
            f"https://api.apify.com/v2/acts/{self._actor}/run-sync-get-dataset-items",
            params={"token": token},
            json={"categoryOrProductUrls": [{"url": search_url}],
                  "maxItemsPerStartUrl": limit, "maxSearchPagesPerStartUrl": 1,
                  "scrapeProductDetails": False, "countryCode": "US"},
            timeout=180,
        )
        out = []
        for it in (r.json() if isinstance(r.json(), list) else []):
            po = it.get("price") or {}
            price = _f(po.get("value") if isinstance(po, dict) else po)
            if not price:
                continue
            if (po.get("currency") if isinstance(po, dict) else "USD") not in ("USD", "$"):
                continue                            # keep the USD assumption downstream relies on
            asin = it.get("asin")
            out.append(Product(
                id=f"amazon-{asin or it.get('title','')[:40]}",
                title=(it.get("title") or query)[:120],
                brand="Amazon", category="product", price=round(price, 2), currency="USD",
                url=f"https://www.amazon.com/dp/{asin}" if asin else "",  # no url field → build from ASIN
                source=self.name, image_url=it.get("imageUrl"),
            ))
        return out
```

Two field-mapping notes the actor forces on you: its `price` is a `{value, currency}` **object**, not a number; and it returns **no product URL**, so you reconstruct the canonical one from the `asin` (`amazon.com/dp/<ASIN>`). Everything else maps onto the shared `Product` exactly like the other connectors — which is the whole point of the protocol: a new retailer is a new class, nothing downstream changes.

<Callout tone="warn">
**Amazon costs money — so it's off by default.** There is no free way to source Amazon: the Apify Amazon actors are pay-per-event or monthly-rental (the `junglee` one is a 14-day trial then ~$40/mo), Amazon's PA-API needs an approved affiliate with prior sales, and direct scraping is blocked. So `AmazonSource` — and the other metered connectors (the Apify Google-Shopping actor, Firecrawl) — carry `metered = True` and their `available()` returns `False` unless you explicitly opt in with `DEALFINDER_ENABLE_PAID_SOURCES=1`. **The default app runs entirely on free sources** (eBay Browse API, RapidAPI free tier, BestBuy, Shopify, iTunes) and never touches a service that can charge you. This is a deliberate pattern worth copying: a paid capability should be *opt-in*, never a footgun that quietly bills you.
</Callout>

<Callout tone="note">
**Two other things to know once you *do* opt in.** (1) The Amazon actor takes ~20-25 s per run, so `AmazonSource` is **tier 2** — Part 9's aggregator only escalates to it when the fast tier-1 APIs come up thin, which for common queries they don't; force it with the `DEALFINDER_TARGET_RESULTS` coverage-audit knob. (2) If you want Amazon on *every* search without the latency tax, the answer isn't tier 1 (that adds ~25 s to all searches) — it's an async parallel fan-out with a per-source timeout, or caching Amazon results into the pgvector store (Part 13) so they serve instantly.
</Callout>

## ShopifySource: the public product feed

Most Shopify stores expose a paginated product catalog at `/products.json`. Shopify [documents this endpoint](https://shopify.dev/docs/api/storefront) for developers; it is indexed by search engines; it requires no key or authentication. The `ShopifySource` treats it as a tier-3 public structured feed.

```python
# live_sources.py — ShopifySource.search() (real implementation, abridged)
def search(self, query: str, limit: int = 15) -> list[Product]:
    tokens = [t for t in re.findall(r"[a-z0-9]+", query.lower()) if len(t) > 2]
    out: list[Product] = []
    for store in self._stores():
        try:
            r = httpx.get(
                f"https://{store}/products.json",
                params={"limit": 250},
                headers={"User-Agent": "Mozilla/5.0"},
                timeout=15,
                follow_redirects=True,
            )
            if r.status_code != 200:
                continue
            per_store = 0
            for p in r.json().get("products", []):
                tags = p.get("tags") or []
                if isinstance(tags, str):
                    tags = tags.split(",")
                hay = f"{p.get('title', '')} {p.get('product_type', '')} {' '.join(tags)}".lower()
                if tokens and not all(t in hay for t in tokens):
                    continue
                v = (p.get("variants") or [{}])[0]
                price = _f(v.get("price"))
                if not price:
                    continue
                # … append Product …
                per_store += 1
                if per_store >= limit:
                    break
        except Exception:
            continue
    return out
```

The query-matching logic is token-based: `re.findall(r"[a-z0-9]+", query.lower())` splits the query into tokens of length > 2, and a product matches only if every token appears somewhere in `title + product_type + tags`. For "noise cancelling headphones" the tokens are `["noise", "cancelling", "headphones"]` — all three must be present for the product to make it through.

<RateLimitGuard />

Two design decisions in the loop protect against being blocked. First, `timeout=15` caps each store at fifteen seconds; a store that hangs drops silently via the `except Exception: continue` at the bottom. Second, `per_store >= limit` stops after `limit` matching products per store, so you never pull a 10,000-item catalog for a query that has three matches.

The `DEFAULT_STORES` list in the class is the set of Shopify stores the companion probed in July 2026 as confirmed to expose `/products.json`. Override it via `SHOPIFY_STORES` (comma-separated domains) to point the connector at electronics-specific stores relevant to your deployment.

```python
# Verified to expose /products.json (probed 2026-07):
DEFAULT_STORES = [
    "deathwishcoffee.com", "www.allbirds.com", "www.kith.com", "chubbiesshorts.com",
    "brooklinen.com", "drsquatch.com", "peakdesign.com", "tentree.com",
    "www.spigen.com", "www.hexclad.com",
]
```

For noise-cancelling headphones, `peakdesign.com` (camera bags, not headphones) and `spigen.com` (phone cases) would return zero matches from the token filter. That is correct behavior — the filter is the guard.

## FirecrawlSource: broad-web fallback

`FirecrawlSource` is the last escalation. It issues a search query to Firecrawl's `/v1/search` endpoint, which returns page-level results — titles, URLs, and description snippets. The connector extracts prices from the description text with a regex and discards results without a credible price:

<Callout tone="note">
**Get your Firecrawl key (free, ~2 minutes).** [Firecrawl](https://www.firecrawl.dev/) is a crawl-and-extract API: give it a URL or a search query and it fetches the page (rendering JavaScript where needed) and returns clean markdown or structured JSON — the messy HTML-to-data step as a service. DealFinder uses only its `/v1/search` endpoint, as the broadest, noisiest tier-4 source.
1. Sign up at [firecrawl.dev](https://www.firecrawl.dev/) (GitHub/Google sign-in).
2. Your API key (`fc-…`) is on the dashboard's **API Keys** page; the free plan includes enough one-time credits for this course.
3. Add `FIRECRAWL_API_KEY=fc-…` to the companion's `.env`.
</Callout>

```python
# live_sources.py — FirecrawlSource.search() (real implementation, abridged)
_SKIP = {
    "rtings.com", "nytimes.com", "techradar.com", "cnet.com", "tomsguide.com",
    "wired.com", "theverge.com", "pcmag.com", "forbes.com", "reddit.com",
    "youtube.com", "wikipedia.org", "wirecutter.com", "businessinsider.com",
}

def search(self, query: str, limit: int = 10) -> list[Product]:
    key = os.getenv("FIRECRAWL_API_KEY")
    if not key:
        return []
    r = httpx.post(
        "https://api.firecrawl.dev/v1/search",
        headers={"Authorization": f"Bearer {key}"},
        json={"query": f"{query} buy price", "limit": limit},
        timeout=60,
    )
    out = []
    for it in (r.json().get("data") or []):
        m = re.search(r"\$\s?([0-9][0-9,]*(?:\.[0-9]{2})?)", it.get("description") or "")
        price = _f(m.group(1)) if m else None
        if not price or not (1 <= price <= 100000):
            continue
        dom = urlparse(it.get("url") or "").netloc.replace("www.", "") or "web"
        if dom in self._SKIP:
            continue
        out.append(Product(
            id=f"firecrawl-{(it.get('url') or it.get('title') or '')[:60]}",
            title=(it.get("title") or query)[:120],
            brand=dom,
            category="product",
            price=price,
            url=it.get("url") or "",
            source=f"{self.name}:{dom}",
            image_url=None,
        ))
    return out
```

Three filters gate the output. The price regex `\$\s?([0-9][0-9,]*(?:\.[0-9]{2})?)` looks for a dollar-sign amount in the description snippet — if the snippet does not mention a price, the result is not a buyable listing and gets dropped. The `1 <= price <= 100000` sanity check guards against a description like "$0 down" or a "$1M yacht" parsing through. The `_SKIP` domain set drops editorial and review sites — `rtings.com`, `wirecutter.com`, `techradar.com` quote prices to inform, not to sell.

The `brand=dom` assignment is intentional: for a Firecrawl result, the closest thing to a source identifier is the domain name. The title-brand extractor from Part 1 (`title_brand()`) runs downstream and overwrites this with the actual manufacturer name, but preserving the domain as `brand` lets you audit which retailer each result came from before normalization.

<Callout tone="warning">
**Check robots.txt before using FirecrawlSource in production.** Firecrawl respects `robots.txt` by default in its managed crawls, but when you pass a `query` to `/v1/search`, Firecrawl is running the web search for you. Your responsibility is to verify that the domains it returns allow the downstream use you intend. The `_SKIP` list removes the obvious editorial sites; add any domain that explicitly disallows scraping in its ToS or `robots.txt`.
</Callout>

If you have never actually read one: `robots.txt` is a plain-text file at the domain root (`https://example-retailer.com/robots.txt`) that tells crawlers which paths are off-limits, per user-agent. A typical retailer's file looks like:

```text
User-agent: *
Disallow: /checkout/
Disallow: /account/
Allow: /products/

User-agent: GPTBot
Disallow: /
```

Read it as: any crawler (`*`) may fetch product pages but not checkout or account paths, and the `GPTBot` user-agent is banned from the whole site. `Disallow: /` under `User-agent: *` means the site opts out of crawling entirely — that is the signal to leave the domain out of your source list. It is a convention, not an access control — which is exactly why honoring it is the ethical baseline rather than a technical hurdle.

## The LIVE_SOURCES list: ordering matters

All connectors are instantiated and stored in a single list at the bottom of `live_sources.py`:

```python
LIVE_SOURCES = [
    EbaySource(),
    RapidApiSource(),
    BestBuySource(),
    AmazonSource(),      # tier 2 — Amazon via the Apify junglee actor
    ApifySource(),
    ShopifySource(),
    FirecrawlSource(),
    ItunesSource(),
]
```

The order is deliberate. The aggregator in Part 9 iterates `LIVE_SOURCES` and calls `.search()` on each connector that reports `.available() == True`. A connector with no key set returns `[]` and is effectively skipped. The ordering means:

1. Tier-1 connectors run first (eBay, RapidAPI, BestBuy) — fast, reliable, data quality is highest.
2. Tier-2 managed scraping (Amazon, Apify) runs next — slower (up to 180s) but structured output.
3. Tier-3 public feed (Shopify) runs after Apify — keyless but subject to store availability.
4. Tier-4 broad-web fallback (Firecrawl) runs last — noisiest output, kept as the final escalation.
5. `ItunesSource` sits at the end: it is flagged `fallback_only = True` (a media catalog, not a retail electronics source); Part 9 checks this flag and skips it for non-media queries.

This ordering means that when the dedup step in Part 9 collapses duplicates, the tier-1 listing wins by price rather than by arrival order: if BestBuy and Shopify both have the same Anker Soundcore Q20i, the dedup key (normalized title + extracted brand) is the same, and the cheaper one keeps regardless of which connector returned it first.

## Worked example: noise-cancelling headphones across all sources

The anchor query is "noise cancelling headphones" — 15 items in the snapshot, median $162.97. Here is what each source tier contributes in the real multi-source run:

**Tier 1 (RapidAPI + BestBuy + eBay):** the headphones subset includes the four hero-cast products. At the end of Part 3's dedup pass:

| Product | Price | Source | Verdict |
|---|---|---|---|
| Sony WH-1000XM5 | $162.97 | RapidAPI:Costco | FAIR |
| Anker Soundcore Q20i | $44.99 | RapidAPI:Walmart | DEAL |
| Bose QuietComfort 45 | $46.00 | RapidAPI:store | SUSPICIOUS |
| Sony WH-1000XM6 | $399.99 | BestBuy | OVERPRICED |

The Sony WH-1000XM5 also appears at $248 from Macy's in the raw tier-1 output. After title-brand extraction both listings produce key `sony|sony wh-1000xm5 wireless...`; the dedup step (first introduced in Part 1 and upgraded to cosine-based in Part 9) keeps the $162.97 Costco listing and drops the $248 Macy's listing with a log entry.

**The deal-score recap on the hero cast:** residual = predicted_fair − actual; residual_frac = residual / predicted_fair. The model assigns $285.15 as the fair price for both the XM5 and the Bose QC45 — both are tier-4 flagships with the same feature vector. That shared fair price is what separates the Anker (honest budget deal, residual_frac 0.585) from the Bose (suspicious, residual_frac 0.839): both list at ~$45, both are 72% under median (median_signal ~0.72), but only the Bose is 84% below its model-predicted fair price. The suspicious threshold is median_signal >= 0.70 AND residual_frac > 0.70 — the Bose crosses both; the Anker does not.

**Tier 2 (Apify):** the Google Shopping actor surfaces retailers the RapidAPI endpoint missed — smaller chains and regional stores. These come in through `ApifySource`, normalize via the same `to_products()` path, and feed the same dedup logic. No novel code is required; the architecture from Part 1 absorbs them.

**Tier 3 (Shopify):** the default store list does not carry consumer headphones, so this query returns zero results. That is expected and correct — the Shopify connector is most useful for niche categories (camera accessories, outdoor gear) where specialty DTC brands sell direct. Override `SHOPIFY_STORES` with a list of audio-specific storefronts to change this.

**Tier 4 (Firecrawl):** for "noise cancelling headphones buy price", Firecrawl returns a mix of product pages and editorial results. The `_SKIP` list drops the editorial domains; the price regex filters the remainder. What survives is a handful of long-tail retailers — the kind of small independent store that would otherwise be invisible to the aggregator. These feed into the same dedup + deal-score pipeline.

The net result: more coverage, more price points to median against, and therefore a better-calibrated median signal. The $162.97 median from the snapshot was computed over 15 headphone listings; a live run with all four source tiers active would produce more listings and potentially a slightly different median. The snapshot median is fixed for reproducible tests; the live median is computed fresh per query.

## Testing scrapers without hitting live sites

Every connector in `live_sources.py` has a corresponding offline test in `tests/test_live_sources.py` and `tests/test_scraper_source.py`. The pattern is consistent: mock the HTTP layer with `respx`, set env vars via `monkeypatch`, run `.search()`, and assert on the parsed `Product` fields.

```python
# tests/test_live_sources.py (real test — FirecrawlSource)
@respx.mock
def test_firecrawl_keeps_priced_results_skips_reviews(monkeypatch):
    monkeypatch.setenv("FIRECRAWL_API_KEY", "test")
    respx.post("https://api.firecrawl.dev/v1/search").mock(
        return_value=httpx.Response(200, json={"data": [
            {"title": "Buds", "url": "https://www.bestbuy.com/buds",
             "description": "Great buds $99.99 today"},
            {"title": "Best of 2026", "url": "https://rtings.com/best",
             "description": "our pick at $35"},
            {"title": "No price", "url": "https://shop.example/x",
             "description": "no price mentioned"},
        ]})
    )
    out = FirecrawlSource().search("buds")
    assert len(out) == 1            # review domain + price-less dropped
    assert out[0].price == 99.99
    assert "bestbuy.com" in out[0].source
```

This test exercises all three filters in one call: the `rtings.com` result is in `_SKIP`, the "No price" result has no dollar-sign match, and only the BestBuy result makes it through. The test passes with no network access.

The same pattern applies to `ShopifySource` and `ApifySource`:

```python
# tests/test_live_sources.py (real test — ShopifySource)
@respx.mock
def test_shopify_filters_catalog_by_query(monkeypatch):
```

The `ScraperSource` class (in `dealfinder/sources.py`) gets its own test in `tests/test_scraper_source.py` — it parses a static HTML fixture rather than calling any live URL:

```python
# tests/test_scraper_source.py (real test)
def test_scraper_parses_fixture():
    items = list(ScraperSource(["data/fixtures/listing.html"], "https://shop.ex").products())
    p = items[0]
    assert p.id == "rr2"
    assert p.brand == "RidgeRunner"
    assert p.price == 232.0
    assert p.source == "scrape"
```

This shows the general `ScraperSource` (which parses CSS-selected `div.product` nodes) versus the specialized `ShopifySource` and `FirecrawlSource` classes that know their source's specific JSON shape. The distinction matters if you ever need to add a custom HTML parser for a specific retailer: inherit from `ScraperSource` or write a new class that follows the `DealSource` protocol.

Run all scraper-related tests:

```bash

```

All tests run without network access. The `respx.mock` decorator intercepts HTTP before it leaves the process.

   ```bash
   python -c "
   from dealfinder.live_sources import ApifySource

   ```
   **Expect:** US retail listings, every row `USD`. **If you see 0 rows:** check `APIFY_TOKEN`; if the run errors, the actor may have queued — rerun once.

   ```bash
   python -c "
   from dealfinder.live_sources import ShopifySource
   print(len(ShopifySource().search('phone case', limit=5)), 'results')"
   ```
   **Expect:** several results (Spigen/Peak Design carry cases). **Searching `headphones` returns 0 — that is correct behavior**, not a bug: the token filter only passes products the niche store list actually sells.

   ```bash

   from dealfinder.live_sources import FirecrawlSource
   ```

   **Expect:** a handful of rows from retail domains, none from the `_SKIP` editorial list — and expect noise (category pages, promo prices). That noise is why Firecrawl is tier 4.
