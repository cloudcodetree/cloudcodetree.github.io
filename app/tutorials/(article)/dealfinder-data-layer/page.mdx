## The problem: messy real data is the curriculum

Pull any broad electronics query from Google Shopping and you get data that misbehaves. `deal_pct` — the percentage below the query median — bottoms out at −3785% on a mispriced outlier in our snapshot and peaks at +91.7% on an accessory mislisting. That range is not a calibration error. It is the signal landscape every technique in this course navigates.

Here is a slice of the raw `deal_pct` distribution across all 270 items in the snapshot:

```
min  : −3785%   ← mispriced outlier (still there; not sanitized here)
p10  :  −140%
p50  :     0%   ← query median, by construction
p90  :  +48%
max  :  +91.7%  ← accessory / mislisting
```

The naive deal signal is broken — which is exactly why Parts 3 onward build a price model to replace it. You need to see the broken version first.

## The normalized schema

Before any connector runs, define the shape everything downstream receives. The snapshot item schema is flat and typed:

```python
# dealfinder/schema.py
class Product(BaseModel):
    id: str
    title: str
    brand: str | None          # WARNING: often the retailer, not the manufacturer
    category: str              # audio, computers, displays, peripherals, …
    price: float
    currency: str = "USD"
    url: str
    source: str                # e.g. "RapidAPI:Costco" — connector : retailer
    image_url: str | None = None
    marketplace: str | None = None   # "RapidAPI", "Apify" — where the offer was seen
    condition: str = "new"           # new / refurb / used (parsed from title)
    specs: dict[str, str] = {}
    price_history: list[PricePoint] = []
```

Pydantic validates and coerces on the way in. Every connector produces a `Product`; every later part consumes it. `brand` is typed as optional and annotated with a warning because, as you'll see in the next section, trusting it blindly is a bug.

## Stand up the Google Shopping connector

The `RapidApiSource` in `dealfinder/live_sources.py` wraps the Real-Time Product Search endpoint. Connecting is three steps: set the env var, run one query, inspect the raw JSON.

```bash
# .env
RAPIDAPI_KEY=your_key_here
```

```python
# step-01a: connector skeleton
from dealfinder.live_sources import RapidApiSource

src = RapidApiSource()
products = src.search("noise cancelling headphones", limit=15)

for p in products[:3]:
    print(f"{p.brand:30s} | {p.title[:55]:55s} | ${p.price:.2f}")
```

Running this against the live API gives output like:

```
Costco                         | Sony WH-1000XM5 Wireless Industry Leading...   | $162.97
Macy's                         | Sony WH-1000XM5 Wireless Industry Leading...   | $248.00
Walmart - COWIN                | COWIN E7 Active Noise Cancelling Headphones ... | $29.99
```

The first thing you notice: `brand` is "Costco" and "Macy's". Those are retailers, not manufacturers. The Sony WH-1000XM5 appears twice — same product, two stores, two prices. Both problems need fixing before the data is usable for anything.

## The brand field lie: 154 of 270 rows hold the retailer

Load the full snapshot and count how many `brand` values are retailer strings rather than manufacturer names:

```python
from dealfinder.snapshot import load_snapshot

items = load_snapshot("data/snapshots/electronics-2026-07.json")
print(len(items))   # 270

# Sample the raw brand field
for item in items[:8]:
    print(repr(item["brand"]))
```

```
'Costco'
'Macy’s'
'Walmart - COWIN'
'Target'
'mountainlifestyle.ca'
'Anker'
'Sony'
'Best Buy'
```

Of the 270 rows, **156 have a `brand` value that is a retailer string** — a marketplace name, a store URL fragment, or a vendor bundle like "Walmart - COWIN". Only the remaining 114 happen to carry the actual manufacturer. Using `brand` directly in a price model or brand-tier ranking would poison the features for more than half the data.

The fix: extract the true manufacturer from the `title`, where it reliably lives.

## Normalize titles, extract the real manufacturer

`dealfinder/features.py` implements `title_brand()` — a greedy regex match over a vocabulary of ~70 known electronics manufacturers, longest match first, with a capitalized-first-token fallback:

```python
# dealfinder/features.py (abridged)
KNOWN_BRANDS = (
    "Amazon Basics", "Google Nest", "Ultimate Ears", "Western Digital",
    "Anker", "Soundcore", "Bose", "Sony", "JBL", "Samsung", "Logitech",
    # … 60+ more …
)
_BRAND_LIST = sorted(dict.fromkeys(KNOWN_BRANDS), key=len, reverse=True)  # longest first
_BRAND_PATTERNS = [
    (b, re.compile(rf"\b{re.escape(b)}\b", re.IGNORECASE)) for b in _BRAND_LIST
]

def title_brand(title: str) -> str | None:
    for canonical, pat in _BRAND_PATTERNS:
        if pat.search(title):
            return canonical
    # Fallback: capitalized first token
    first = title.strip().split()[0].strip(".,")
    if first and first[0].isupper() and len(first) > 1:
        return first
    return None
```

No LLM. No API call. About 15 lines of deterministic regex. Verify it against the hero cast:

```python
from dealfinder.features import title_brand

cases = [
    ("Sony WH-1000XM5 Wireless Industry Leading Noise Canceling Headphones", "Sony"),
    ("COWIN E7 Active Noise Cancelling Headphones", "Cowin"),
    ("Bose QuietComfort 45 Bluetooth Wireless Over Ear Headphones", "Bose"),
    ("Anker Soundcore Q20i Active Noise Cancelling Headphones", "Anker"),
]
for title, expected in cases:
    result = title_brand(title)
    status = "✓" if result == expected else "✗"
    print(f"{status} '{result}' from: {title[:55]}")
```

```
✓ 'Sony' from: Sony WH-1000XM5 Wireless Industry Leading Noise Ca
✓ 'Cowin' from: COWIN E7 Active Noise Cancelling Headphones
✓ 'Bose' from: Bose QuietComfort 45 Bluetooth Wireless Over Ear He
✓ 'Anker' from: Anker Soundcore Q20i Active Noise Cancelling Headph
```

Once you have the true manufacturer, `brand_tier()` maps it to a price-tier rank (1–4): Sony and Bose are tier 4 flagships; Anker is tier 2 value. That tier is one of the three features the price model learns from in Part 3.

## Dedup: same product, or two offers to compare?

The connector returned Sony WH-1000XM5 headphones from Costco at $162.97 and from Macy's at $248.00. Should those collapse into one row? For a deal aggregator the answer is subtler than it looks — and the real data makes it concrete. `dedup_key` + `ingest` in `dealfinder/ingest.py` do an **exact-match** collapse: identical brand *and* title, keep the cheapest.

```python
# dealfinder/ingest.py
def dedup_key(p: Product) -> str:
    """Exact-match collision key: same brand + title. Cross-retailer offers and
    near-duplicate titles are NOT collapsed here — that is the semantic (cosine)
    dedup in Part 9."""
    return f"{(p.brand or '').strip().lower()}|{p.title.strip().lower()}"

def ingest(sources: list[DealSource]) -> list[Product]:
    """Pull from every source; when the exact same product appears twice, keep the cheapest."""
    best: dict[str, Product] = {}
    for src in sources:
        for p in src.products():
            k = dedup_key(p)
            if k not in best or p.price < best[k].price:
                best[k] = p
    return list(best.values())
```

Now run the real Sony rows through it — the actual keys from the frozen snapshot:

1. **Costco row** — raw `brand="costco.com"`, title `"Sony WH-1000XM5 Wireless Headphones"`, `$162.97`. Key: `costco.com|sony wh-1000xm5 wireless headphones`.
2. **Macy's row** — raw `brand="Macy's"`, title `"SONY WH-1000XM5 Wireless Noise-Canceling Headphones"`, `$248.00`. Key: `macy's|sony wh-1000xm5 wireless noise-canceling headphones`.
3. **The keys differ — on both halves.** The raw `brand` is a *retailer* (Part 1's other problem), and the titles aren't byte-identical either ("Wireless Headphones" vs. "Wireless Noise-Canceling Headphones"). So `ingest` keeps **both** rows.

And that is the right call. A deal aggregator's whole job is to show the same product across stores so you can compare — collapsing the $248 listing away would *hide* a data point, not clean one. Exact-match dedup exists to catch a feed that returns the *identical* row twice, not to merge genuine cross-retailer offers.

Recognizing that these two *are* the same product — despite different retailer brands and slightly different titles — is a harder, semantic problem. That is exactly what Part 9 solves with embedding-based cosine dedup (threshold 0.90): it measures that the two titles *mean* the same thing and merges them with an audit log. **Part 1 surfaces the problem; Part 9 has the machinery to solve it.**

<DedupMerge />

When an exact duplicate *is* collapsed, the drop is logged, not silent — so you can audit which listings were merged and why. That auditability matters more than it seems: in Part 9 the cosine-dedup pass (threshold 0.90) runs the same keep-cheapest logic at embedding distance to merge cases like this Sony pair, and the log is what lets you catch false positives before they hide a real offer.

## Freeze the snapshot

`data/build_snapshot.py` orchestrates the full pipeline: issue 18 queries to the live connector, normalize, dedup, and write `electronics-2026-07.json`. You do not need to run this — the snapshot is already committed. But understanding the freeze is important for reproducibility:

```python
# data/build_snapshot.py (abridged)
QUERIES = [
    "noise cancelling headphones",
    "gaming laptop",
    "ultrawide monitor",
    "mechanical keyboard",
    "webcam",
    "external SSD",
    "wireless mouse",
    "portable bluetooth speaker",
    "smart home hub",
    "graphics card",
    # … 8 more …
]

# Rate-limited: 1 req/s to stay within the free tier.
# Outputs: data/snapshots/electronics-2026-07.json
# File size: ~180 KB
# SHA pinned in a comment at the top of this file so regenerated snapshots
# are identifiable.
```

The snapshot is the stable ground truth. Every quoted number in this course — the $162.97 median, the 156-row brand-retailer count, the −3785% outlier — is a fixed property of this committed file. If you regenerate it, those numbers will differ and the prose will be wrong. Do not regenerate unless you are intentionally updating the course baseline.

## Reproducibility checks

The following assertions must pass against `electronics-2026-07.json`. They are pinned in `tests/test_part01.py` and run in CI:

```python
import statistics
from dealfinder.snapshot import load_snapshot, to_products
from dealfinder.ingest import dedup_key, ingest

items = load_snapshot()

# ── snapshot count ───────────────────────────────────────────────────────────
assert len(items) == 270

# ── brand field is retailer-polluted (the Part 6 audit) ──────────────────────
# 154 of 270 rows carry a retailer token in `brand` instead of the manufacturer.
retailers = ["Walmart", "Target", "Costco", "Macy", "Best Buy", "Amazon",
             "mountainlifestyle", "kohl"]
polluted = sum(
    1 for x in items
    if any(r.lower() in (x.get("brand") or "").lower() for r in retailers)
)
assert polluted == 154              # don't trust `brand`; extract from the title

# ── hero-cast: noise cancelling headphones ───────────────────────────────────
ncb = [i for i in items if i["query"] == "noise cancelling headphones"]
assert len(ncb) == 15
prices = sorted(float(i["price"]) for i in ncb)
assert abs(statistics.median(prices) - 162.97) < 0.01   # query-median pinned

# ── dedup: cross-retailer XM5 offers are BOTH kept (compare, don't collapse) ──
xm5 = [p for p in to_products(items) if "wh-1000xm5" in p.title.lower()]
assert len(xm5) == 2                             # Costco $162.97 AND Macy's $248
assert len({dedup_key(p) for p in xm5}) == 2     # distinct keys (retailer + title differ)

# ── …but a genuine exact duplicate DOES collapse, keeping the cheaper ─────────
from dealfinder.schema import Product
class _StaticSource:
    def __init__(self, ps): self._ps = ps
    def products(self): return self._ps
dupes = [Product(id="a", title="Anker Q20i", brand="Anker", category="audio",
                 price=54.99, url="u", source="feed"),
         Product(id="b", title="Anker Q20i", brand="Anker", category="audio",
                 price=44.99, url="u", source="feed")]
kept = ingest([_StaticSource(dupes)])
assert len(kept) == 1 and kept[0].price == 44.99

# ── deal_pct outliers are still present (not sanitized in Part 1) ─────────────
deal_pcts = [float(i["deal_pct"]) for i in items]
assert min(deal_pcts) < -3000
assert max(deal_pcts) > 90
```

Run them with:

```bash
pytest tests/test_part01.py -v
# 6 passed
```

Every assertion passes against the committed snapshot. If you have regenerated the snapshot, expect failures — that is by design; the frozen file is what keeps these numbers (and every later lesson's) reproducible.
