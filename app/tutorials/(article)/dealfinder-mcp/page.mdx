# Expose It as an MCP Server

**TL;DR: You built tools; now make them callable from any AI client. The Model Context Protocol is the "USB-C for AI tools" — write your server once and Claude Code, Claude Desktop, or any MCP client can use DealFinder's `score_deal`, `recommend`, and `search_deals`. A few lines with the official SDK.**

In Part 8 your agent called DealFinder's tools internally. MCP turns those same tools *outward* — into a standard interface other AI apps consume. This is fast-becoming table stakes for AI engineers: shipping capabilities as MCP servers instead of bespoke integrations.

## The server, in a few lines

`FastMCP` turns a typed function into a tool: the name, docstring, and type hints become the schema the client sees. Here's the whole server (abridged):

```python
# dealfinder/mcp_server.py
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("dealfinder")

@mcp.tool()
def score_deal(product_id: str) -> dict:
    """Price, predicted fair price, and deal score (positive = under fair)."""
    p = _catalog[_idx[product_id]]
    return {"id": product_id, "price": p.price,
            "deal_score": round(deal_score(p.price, _fair[product_id]), 3)}

@mcp.resource("dealfinder://catalog/stats")
def catalog_stats() -> str:
    return f"{len(_catalog)} products; average price ${_avg:.0f}"

@mcp.prompt()
def find_a_deal(category: str = "tent") -> str:
    return f"Find the best-value {category} and explain why it's a good deal."

if __name__ == "__main__":
    mcp.run()
```

Every tool you built earlier — search, scoring, recs — registers the same way. The type hints *are* the API contract; no separate schema to maintain.

## Use it from Claude Code

Point an MCP client at the server. For Claude Code, add it to your MCP config:

```json
{
  "mcpServers": {
    "dealfinder": {
      "command": "python",
      "args": ["-m", "dealfinder.mcp_server"]
    }
  }
}
```

Now `score_deal`, `recommend`, and `search_deals` show up as callable tools in your AI client — your whole DealFinder backend, one protocol away.

<Callout tone="note">
**How this scales in production.** Serve over HTTP/SSE instead of stdio for remote clients, add auth (OAuth) and per-tool rate limits, validate every argument (Part 10), and emit traces for each call (Part 14). Publish to an MCP registry so others can discover it. The tool definitions don't change — only the transport and the guardrails around them.
</Callout>
