# Is It a Good Deal?

**TL;DR: "72% off" sounds great until it's a $329 flagship listed at $46 with no explanation. A single-signal median score can't tell the Anker Q20i (genuinely cheap) from the Bose QC45 (a trap). Train a price model from scratch — no scikit-learn — that predicts what a product *should* cost from its category, extracted brand, and condition. Blend its residual with the median signal to catch the trap. That's the two-signal deal score.**

## Why the naive signal fails

Part 1 built the snapshot: 270 real electronics listings from 18 queries. Every item already carries `deal_pct` — the percentage below the same-query cross-source median. It's fast and model-free. So why isn't it enough?

Run `python -m dealfinder.train_model` on the full corpus and ask for the top "deals" by raw `deal_pct`:

```
$ python -m dealfinder.describe_deal_pct
deal_pct range: -3785.1% to +91.7%

top 5 by deal_pct (naive):
  1. Kindle cover accessory     $10.75  +91.7%   (query: "kindle paperwhite")
  2. Bose QuietComfort 45       $46.00  +71.8%   (query: "noise cancelling headphones")
  3. Anker Soundcore Q20i       $44.99  +72.4%   (query: "noise cancelling headphones")
  ...
```

Three things jump out:

1. **An accessory is ranked #1.** A $10.75 Kindle cover sits in the same "kindle paperwhite" query bucket as a $139 reader. The median is pulled up by the device, so the cover looks like a 91.7% discount. The "deal" is a category mismatch.
2. **A $329-MSRP flagship at $46 ranks #2.** The Bose QuietComfort 45 is listed at $46 — 71.8% under the $162.97 headphone median. The Anker Q20i, also at ~$45, ranks right next to it at 72.4% under. Both look identical on this signal.
3. **The outlier at −3785%.** One mispriced listing pulls the full-corpus minimum to a number that makes every ranking comparison meaningless.

The signal breaks on broad data because it has no opinion about what a product *should* cost — it only knows where it sits relative to a noisy peer group. A $46 Bose QC45 could be:
- a refurb or mislisted item (the likely truth), or
- a genuine markdown (possible, but requires confirmation)

The median can't tell. A price model can.

## Features the model sees

A model never sees "a Bose QuietComfort 45." It sees numbers. **Feature engineering** is choosing which numbers. For broad electronics, three features generalize across every category in the snapshot:

```python
# dealfinder/features.py
FEATURE_NAMES = ["category_code", "brand_tier", "condition_code"]

def featurize(p: Product) -> list[float]:
    cond = p.condition if p.condition else parse_condition(p.title)
    return [
        float(category_code(p.category)),   # audio=3, computers=9, …
        float(brand_tier(p.title)),          # 1–4; extracted from the title, not p.brand
        float(condition_code(cond)),         # new=2, refurb=1, used=0
    ]
```

Two design decisions worth understanding:

**The `brand` field is useless.** Part 1 discovered this: 154 of 270 snapshot rows have the *retailer* in `brand` — "Walmart - COWIN", "Target", "mountainlifestyle.ca". Trusting `p.brand` would poison the model with retailer names. So `brand_tier()` extracts the actual manufacturer from the *title* using a greedy known-brand vocabulary, then maps it to a tier:

```python
# tier 4 — premium flagships: Apple, Sony, Bose, Sennheiser, Garmin
# tier 3 — strong majors: Samsung, LG, Dell, Logitech, JBL, Beats, …
# tier 2 — value / mid brands: Anker, Soundcore, JLab, Skullcandy, …
# tier 1 — everything else / unknown
```

For the Bose QC45, `title_brand("Bose QuietComfort 45 …")` → `"Bose"` → tier 4. For the Anker Q20i, `title_brand("Anker Soundcore Q20i …")` → `"Anker"` → tier 2.

**Condition is parsed from the title, not a field.** The Bose QC45 listing has no condition token — no "refurb", "renewed", "open box". So `parse_condition(title)` returns `"new"` (the default). This is by design: the **model residual** catches the trap, not a condition flag.

<Callout tone="note">
**Why not use the full title embedding here?** Part 2 introduced embeddings conceptually. The 384-dim `BAAI/bge-small-en-v1.5` title vectors are precomputed and cached in the snapshot — they are the Part 4 upgrade (recommender content similarity) and the Part 21 upgrade (gradient boosting on embeddings). The linear baseline in this part uses the three hand-features above, which are interpretable and enough to demonstrate the two-signal concept. Adding embeddings is what closes the MAE gap from ~\$228 to ~\$138 on the full corpus — that delta is itself a curriculum moment.
</Callout>

## Linear regression from scratch

A linear model predicts price as a weighted sum of features plus an intercept. "Training" means finding the weights `θ` that minimize the total squared error. There is a closed-form solution — the **normal equation**:

```
θ = (Xᵀ X)⁻¹ Xᵀ y
```

where `X` is your feature matrix with a leading column of 1s (so `θ₀` is the intercept), and `y` is the vector of actual prices.

That formula is not magic — it falls out of freshman calculus. The total squared error `‖y − Xθ‖²` is a smooth, bowl-shaped function of the weights: make the line too flat or too steep and the squared gaps grow, so somewhere in between they bottom out. At the bottom of a bowl the gradient is zero, and setting the gradient of `‖y − Xθ‖²` to zero gives `Xᵀ(y − Xθ) = 0` — read that as *the residuals end up perpendicular to every feature column*, meaning no feature has any leftover correlation with the errors that another tilt of the line could exploit. Rearranged, that is `XᵀX θ = Xᵀy`; solving for `θ` is the normal equation. Squaring the error (rather than taking absolute values) is exactly what buys this: a smooth bowl with a single closed-form minimum — at the cost of weighting one $200 miss like a hundred $20 misses.

That is the entire algorithm — no gradient descent, no library:

```python
# dealfinder/dealmodel.py
class LinearModel:
    def fit(self, X, y):
        Xb = _with_bias(X)                                    # prepend a column of 1s
        self.coef_ = np.linalg.pinv(Xb.T @ Xb) @ Xb.T @ y   # the normal equation
        return self

    def predict(self, X):
        return _with_bias(X) @ self.coef_
```

`np.linalg.pinv` is the pseudo-inverse — mathematically identical to the regular inverse when the matrix is full rank, but numerically stable when columns are collinear (which happens in small, structured datasets). The geometry: you are finding the hyperplane that sits as close as possible to every point. What it minimizes is the sum of squared **residuals** — the vertical gaps between the data and the plane:

<Callout tone="note">
**Why this is testable.** Because the normal equation is exact, you can hand the model data generated from *known* weights and assert it recovers them exactly (up to floating-point). That is the strongest kind of correctness check — the first test in the suite.
</Callout>

## Evaluate honestly

Scoring a model on the data it trained on flatters it. The snapshot has 270 items; train on the audio-category subset to get fair-price estimates that reflect what headphones should cost (mixing audio and storage in one fit would dilute the category signal):

```python
# dealfinder/train_model.py
audio = [p for p in products if p.category == "audio"]
audio_model = fit_price_model(audio)   # fit_price_model wraps LinearModel().fit(...)
```

For the full corpus, the from-scratch linear baseline reports its own honest numbers — and the honest number on broad heterogeneous data is deliberately not impressive:

```
$ python -m dealfinder.train_model
trained on 202 listings, tested on 68
  MAE  = $227.89
  R^2  = 0.268   (broad data → weak; see §4/Part 21)

learned price drivers (intercept + per-feature $):
  intercept        +1.4
  category_code    +83.8
  brand_tier       -7.6
  condition_code   +2.8
```

Two metrics, both worth reading precisely. **MAE** (mean absolute error) is the average size of the miss in dollars: predictions here are off by \$227.89 on average — a number in the *units of the target*, which is why it is the metric you can explain to anyone. **R²** is the fraction of price *variance* the model explains, on a scale where 1.0 is perfect and 0.0 means "no better than always predicting the mean price": 0.268 says these three features explain about a quarter of why prices differ — the other three-quarters is in signals the features don't carry (yet).

The dominant driver is `category_code` at **+\$83.8 per code step** — the model captures that electronics categories span a wide price range (accessories vs. computers vs. audio). `brand_tier` has a negative coefficient (−\$7.6) on the full heterogeneous corpus because tier interacts strongly with category; the audio-only model, fitted on the 15-item headphones subset, produces a cleaner coefficient. That is not a bug — it is why fitting per-category (see `audio_model` above) is more interpretable for the hero cast.

The R² of 0.268 is low for a real production model. That is the curriculum: three hand-features on a broad, heterogeneous 270-item corpus leave most price variance unexplained. Part 21 replaces `LinearModel` with sklearn `GradientBoostingRegressor` on the same features plus the 384-dim title embedding — the R² jumps from 0.268 to 0.727 and the MAE falls from \$227.89 to \$138.11 on the full corpus. The `featurize → fit → score` shape stays identical; only the model class swaps out.

<Callout tone="note">
**Temporal split caveat.** The snapshot was captured at a single point in time, so there is no genuine temporal ordering to split on. The training run uses a deterministic 80/20 index split (`seed=0`) and documents this in a code comment. Real temporal split — using older data to train and recent data to test — is the Part 19 topic (dataset engineering and leakage).
</Callout>

## Two-signal deal score

Now the payoff. The model predicts a fair price; a **residual** is the gap between the model's expectation and the actual price:

```python
# dealfinder/dealscore.py
def residual(actual: float, fair: float) -> float:
    """Signed gap: fair − actual. Positive = item is priced BELOW fair = looks cheap."""
    return fair - actual

def residual_fraction(actual: float, fair: float) -> float:
    """Residual as a fraction of the fair price."""
    if fair <= 0:
        return 0.0
    return (fair - actual) / fair
```

The sign convention matters: **large positive residual = the price is suspiciously far below the model's expectation.** A residual_frac of 0.839 means the item is priced at only 16% of what the model says it should cost. For a new listing with no condition token, that is a red flag.

The two-signal verdict blends median and residual:

```python
SUSPICIOUS_RESIDUAL_FRAC = 0.70   # actual < 30% of fair → too-good-to-be-true
DEAL_MEDIAN_FRAC = 0.15           # need ≥15% under the market median to be a deal

def verdict(actual, median, fair) -> Verdict:
    m  = median_signal(actual, median)         # fraction below query median
    rf = residual_fraction(actual, fair)       # fraction below model fair price

    if m >= DEAL_MEDIAN_FRAC and rf >= SUSPICIOUS_RESIDUAL_FRAC:
        return Verdict("suspicious", ...)      # median says deal; model says trap
    if m >= DEAL_MEDIAN_FRAC:
        return Verdict("deal", ...)            # both signals agree: genuine value
    if m < 0:
        return Verdict("overpriced", ...)
    return Verdict("fair", ...)
```

The suspicious condition is `median_signal >= 0.70 AND residual_frac > 0.70`. Both must fire. The Anker Q20i has `residual_frac = 0.585` — it passes the residual guard. The Bose QC45 has `residual_frac = 0.839` — it does not.

## The proof: hero-cast walk-through

Anchor query: **"noise cancelling headphones"**. Snapshot median: **$162.97** (Sony WH-1000XM5 Costco — it sits exactly at the median, so its `median_signal = 0.000`). Headphones subset: **15 items**.

The audio model's fair-price prediction depends on `(category_code=3, brand_tier, condition_code=2)`. Tier-4 flagships (Sony, Bose) map to the same feature vector → same prediction. Tier-2 budget brands (Anker) map to a lower prediction.

| Item | actual | model fair | residual ($) | residual\_frac | median\_signal | verdict |
|---|---|---|---|---|---|---|
| Sony WH-1000XM5 (Costco) | $162.97 | $285.15 | +$122.18 | +0.428 | 0.000 | **FAIR** |
| Anker Soundcore Q20i | $44.99 | $108.33 | +$63.34 | +0.585 | +0.724 | **DEAL** |
| Bose QuietComfort 45 | $46.00 | $285.15 | +$239.15 | +0.839 | +0.718 | **SUSPICIOUS** |
| Sony WH-1000XM6 | $399.99 | $285.15 | −$114.84 | −0.403 | −1.454 | **OVERPRICED** |

The teaching crux is in the middle two rows. **Anker and Bose both sit at roughly $45 — 72% under the $162.97 median.** The naive `deal_pct` cannot separate them; they are tied. Only the model residual distinguishes them: Anker's residual_frac (0.585) is below the 0.70 guard threshold — consistent with a genuine budget-tier value pick. Bose's residual_frac (0.839) clears the threshold because the model, seeing "tier-4 flagship audio, condition=new", predicts $285.15 — Bose and XM5 share the *same* fair price because they share the same feature vector. A tier-4 flagship listed at $46 with no condition token is the signature of a mislisting; the residual catches it while the median is fooled.

Run it:

```
$ python -m dealfinder.train_model

verdicts on "noise cancelling headphones" (median $162.97):
  [suspicious ] $46.00  Bose QuietComfort 45 Wireless Headphones  — 72% under median but 84% under model fair price $285 — too far below to be real (likely refurb/mislisted).
  [deal       ] $44.99  Anker Soundcore Q20i Wireless Headphones  — 72% under the $162.97 median and consistent with the model's $108 fair price — a genuine value pick.
```

The order in the output is: suspicious first (higher median_signal), deal second. The flip you need to see is in the `verdict` field — not in the raw `deal_pct`, where they are indistinguishable.

## Tests that pin the numbers

All the hero-cast values above are not just examples — they are **test assertions** in `companions/dealfinder/tests/test_dealscore.py`. These run against the frozen snapshot on every CI push:

```python
# tests/test_dealscore.py — pinned against electronics-2026-07.json
from dealfinder.dealscore import median_signal, residual, residual_fraction, verdict

SNAP_MEDIAN = 162.97   # anchor query median (spec §3)

def test_median_signal_hero_cast():
    assert median_signal(162.97, SNAP_MEDIAN) == pytest.approx(0.000, abs=0.01)  # XM5 Costco
    assert median_signal( 44.99, SNAP_MEDIAN) == pytest.approx(0.724, abs=0.01)  # Anker Q20i
    assert median_signal( 46.00, SNAP_MEDIAN) == pytest.approx(0.718, abs=0.01)  # Bose QC45

def test_model_residuals_hero_cast(audio_model):
    # Both XM5 and Bose share fair price: same tier-4, audio, new features
    assert audio_model.predict(xm5_features)  == pytest.approx(285.15, abs=5.0)
    assert audio_model.predict(bose_features) == pytest.approx(285.15, abs=5.0)
    assert audio_model.predict(anker_features) == pytest.approx(108.33, abs=5.0)

def test_residual_fraction_guard():
    # Bose: residual_frac > 0.70 (suspicious threshold)
    assert residual_fraction(46.00, 285.15) == pytest.approx(0.839, abs=0.01)
    assert residual_fraction(46.00, 285.15) > 0.70

    # Anker: residual_frac < 0.70 (below suspicious threshold — genuine deal)
    assert residual_fraction(44.99, 108.33) == pytest.approx(0.585, abs=0.01)
    assert residual_fraction(44.99, 108.33) < 0.70

def test_verdict_hero_cast(audio_model):
    assert verdict(44.99, SNAP_MEDIAN, 108.33).label == "deal"
    assert verdict(46.00, SNAP_MEDIAN, 285.15).label == "suspicious"
    assert verdict(162.97, SNAP_MEDIAN, 285.15).label == "fair"
    assert verdict(399.99, SNAP_MEDIAN, 285.15).label == "overpriced"

def test_blended_score_ordering(audio_model):
    # The Anker must outscore the Bose — the guard works
    scores = {
        "anker": blend_deal_score(44.99, SNAP_MEDIAN, 108.33),
        "bose":  blend_deal_score(46.00, SNAP_MEDIAN, 285.15),
        "xm5":   blend_deal_score(162.97, SNAP_MEDIAN, 285.15),
    }
    assert scores["anker"] > scores["bose"]
    assert scores["anker"] > scores["xm5"]

def test_model_mae_within_tolerance(audio_model, test_split):
    assert audio_model.held_out_mae < 85.0   # dollars; real value committed to repo
```

<Callout tone="note">
**How this scales in production.** The `featurize → fit → score` shape you built here is unchanged in Parts 4 and 21. Part 4's recommender reuses `feature_matrix()` as the content-similarity backbone. Part 21 swaps `LinearModel` for sklearn `GradientBoostingRegressor` — the R² moves from 0.268 to 0.727 and the MAE from \$227.89 to \$138.11 on the full corpus (with embeddings), and the Bose trap stays caught. The two-signal blend and the suspicious threshold stay the same. That is the point: good architecture lets you upgrade the model without rewriting the pipeline.
</Callout>

**Part 5 eval gate.** Before the recommender deploys in Part 5, the two-signal score must pass `precision@5 >= 0.80` on a **20-item golden set** drawn from the snapshot — all 15 headphones from the anchor query plus 5 cross-category items, each hand-labeled `deal|fair|suspicious|overpriced`. This gate is defined once (Part 5) and reused identically in the eval, MLOps, inference, and security parts later in the course.
