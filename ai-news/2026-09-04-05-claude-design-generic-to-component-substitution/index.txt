12:Td93,**Before Claude Code starts adding features, run one substitution pass that replaces Claude Design's generic HTML with your actual design system components — otherwise Claude Code builds around the generics and you pay to fix them later.**

**What you'll be able to do after this:** Run a single pre-handoff prompt that maps every generic HTML element to the closest component in your library, before any feature code accumulates.

Claude Design generates valid, styled markup, but it doesn't know your component library. Its output uses `<div class="card">`, `<button class="btn-primary">`, `<input placeholder="Search">`. Your codebase has `<Card>`, `<Button variant="primary">`, `<SearchInput>`. If you hand that file directly to Claude Code and ask it to add feature logic, it writes the feature around the generic elements. Refactoring later costs a full re-review of everything Claude Code touched ([From Prompt to Production — Design Systems Collective](https://www.designsystemscollective.com/from-prompt-to-production-a-designers-step-by-step-workflow-with-claude-design-claude-code-a7705daad026)).

**The substitution prompt — paste this into a Claude Code session after staging the generated file:**

```
Look at [generated-file.tsx]. Compare every div, button, input, anchor,
and paragraph to the components in src/components/. For each element that
maps cleanly to a named component — same role, compatible props — make the
substitution. Preserve all layout classes, spacing, and event stubs exactly.
Do not change behavior. Stop if a mapping is ambiguous; list what you
couldn't map and why.
```

**Three-step walk-through:**

1. **Stage the export.** Copy your Claude Design export into a temporary file at `src/screens/generated-[feature].tsx` — not directly into your component tree.
2. **Run the substitution pass.** Expect 80–90% of elements to map cleanly on a well-maintained component library. Review the ambiguous list manually; "ambiguous" usually means a layout primitive that has no component equivalent, which is correct behavior.
3. **Commit the substituted file.** Now hand it to Claude Code for feature work. Everything Claude Code touches from this point forward is already in your component vocabulary.

**The limit:** The substitution pass handles clear 1:1 analogues. Highly composed layouts — hero sections, complex data grids, multi-level navigation — often contain patterns without a single matching component. The prompt will tell you what it couldn't map; those are the decisions to make manually before proceeding. Don't re-run the substitution pass after feature code accumulates — the ordering matters.

**Pair this with:** the component inventory technique from [this morning's post](/ai-news/2026-09-04-04-claude-design-multi-screen-component-inventory) (keep components consistent across screens) and the project description technique from [today's design post](/ai-news/2026-09-04-07-claude-design-project-description-brand-brief) (seed stylistic consistency upfront). The substitution pass is the bridge between them.
