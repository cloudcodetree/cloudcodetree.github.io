12:Tb52,**LangChain 1.4.0 alpha ships `langchain.mcp.MCPAdapter` — drop in any MCP server URL or local script and your LangGraph agent discovers and calls its tools without a custom wrapper.**

The MCP-to-LangChain gap previously required either a bespoke integration or a separate client library with its own connection management. LangChain 1.4.0-alpha.3 ships a new `langchain.mcp` namespace that handles connection, tool discovery, and schema translation automatically ([LangChain release notes — Releasebot](https://releasebot.io/updates/langchain-ai)).

```python
from langchain.mcp import MCPAdapter
from langgraph.prebuilt import create_react_agent

# Accepts a URL, a local script path, an in-process server, or an MCPConfig
adapter = MCPAdapter("http://localhost:8080/mcp")
tools = await adapter.list_tools()   # discovers + adapts all server tools

agent = create_react_agent("claude-sonnet-5", tools)
result = await agent.ainvoke({"messages": [("user", "your query here")]})
```

Tool discovery is cached by default — `await adapter.list_tools(refresh=True)` repopulates it if a server changes without restarting your process.

For a fleet of servers, `MCPClientGroup` aggregates them behind one client:

```python
from langchain.mcp import MCPClientGroup

group = MCPClientGroup({
    "db":     "http://localhost:8080/mcp",
    "search": "http://localhost:8090/mcp",
})
all_tools = await group.list_tools()   # one list from all servers
agent = create_react_agent("claude-sonnet-5", all_tools)
```

This is particularly useful when you have multiple Claude Code MCP servers — the file-access server, the internal-API server, the DB query server — and want to combine them inside a LangGraph agent without writing a custom fan-out layer.

**Two limits to know upfront:**

1. **This is 1.4.0-alpha.** The `langchain.mcp` interface will shift before the final release. Pin the exact alpha version in your lockfile and watch the [LangChain releases](https://github.com/langchain-ai/langchain/releases) before upgrading. Don't build production dependencies on an alpha API.

2. **stdio servers need an HTTP wrapper.** `MCPAdapter` expects a network endpoint (HTTP/SSE). If your MCP server runs as a local subprocess (stdio transport), you need to expose it over HTTP first — a small FastAPI wrapper around your stdio session is the standard pattern, and Claude Code's own managed MCP servers already enforce this for the same reason.
