12:T9b1,**In Fable 5.1 coding agents, implied-independent calls may serialize instead of batching. A one-sentence turn-scoped system message appended after each tool batch restores parallel execution.**

Fable 5.1 batches tool calls reliably when your request names what to fetch. The exception is coding agents and bash-and-editor harnesses where the next reads are *implied* by the task — there it may issue them one per turn instead of together. No quality loss, but each extra turn costs tokens, a round trip, and wall-clock time in a loop that can run dozens of turns.

**The fix:** append this sentence after each tool-result batch:

```
First privately list what you need next; then request every item that doesn't depend on another's result in this one response.
```

Deliver it as a turn-scoped system message — a `role: "system"` entry with `clear_at: "next_user_message"` (beta header: `mid-conversation-system-clear-at-2026-08-21`). Append a fresh copy after each tool-result batch; leave old copies in the array byte-for-byte. Once cleared, they cost zero input tokens and the model doesn't see them. **Do not edit or delete them**: that restarts the prompt cache from that point and invalidates the thinking blocks that follow.

Without the beta flag, place the sentence in a `text` block inside the user message that carries the `tool_result` blocks — same turn, after the results.

**This is different from `disable_parallel_tool_use`**, which intentionally forces one call per turn for pipelines that need to inspect or rate-limit each result. The nudge is for loops where calls are structurally independent but the model isn't batching them on its own.

**Limit**: the nudge works for implied-independent calls in agentic loops. Calls with genuine ordering dependencies — where each result determines the next call — can't be parallelized regardless of the prompt.
